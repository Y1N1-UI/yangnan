1任务一 · 提示词工程师：不写代码写提示词

任务要求：不写代码写提示词，把 4 项需求翻译给 AI 生成 new Swiper('#wySw4', {...}) 配置；至少迭代 2 轮，保留每轮提示词与 AI 回答，粘进页面逐项验证。

第 1 轮 · 第一版提示词（故意写粗，未逐条列需求）

我的提示词：帮我写一个 Swiper 的配置，要自动播放，效果用 cube 立方体，有圆点分页器，圆点对应 id #wyPag4。

AI 第 1 轮回答

var wySw4 = new Swiper("#wySw4", {
  effect: "cube",
  cubeEffect: { slideShadows: true, shadow: true, shadowOffset: 40, shadowScale: 0.94 },
  autoplay: { delay: 3000 },
  pagination: { el: "#wyPag4" },
});

第 1 轮逐项检查（对照 4 项需求）

需求第 1 轮结果结论
① 无缝循环没写 loop❌ 缺失——到最后一张会停住
② 3.2 秒自动翻页、手动后不停止delay 被擅自定为 3000；没写 disableOnInteraction⚠️ 两处偏差——拖一次自动播放就永久停
③ 圆点分页器可点击写了分页器，没写 clickable⚠️ 圆点只能看不能点
④ 初始效果为 cubeeffect: "cube"✅ 满足

教训："自动播放""有圆点"这类口语化说法，AI 只会给"能跑但缺细节"的代码。需求必须逐条列、参数级地说清楚。

第 2 轮 · 修正版提示词（逐条列出，参数级明确）

我的提示词：请用 Swiper 11 生成配置，必须同时满足以下 4 条，一条都不能少：1. 无缝循环 loop: true；2. 自动翻页每张停留 3200 毫秒，用户手动操作后继续不要停（disableOnInteraction: false）；3. 圆点容器 #wyPag4、可点击跳转（clickable: true）；4. 初始效果为 cube。只输出配置代码和每个参数一行注释。

AI 第 2 轮回答（最终代码）

var wySw4 = new Swiper("#wySw4", {
  loop: true,                          // ① 无缝循环：最后一张接回第一张
  autoplay: {
    delay: 3200,                       // ② 每 3.2 秒自动翻页
    disableOnInteraction: false,       // ② 用户手动操作后自动播放不停止
  },
  pagination: {
    el: "#wyPag4",                     // ③ 圆点分页器容器
    clickable: true,                   // ③ 点圆点可直接跳转
  },
  effect: "cube",                      // ④ 初始效果：3D 立方体
  cubeEffect: { slideShadows: true, shadow: true, shadowOffset: 40, shadowScale: 0.94 },
});

每轮效果实验台（按各轮 AI 回答的原始配置 1:1 复现）

第 1 轮效果 · 有缺陷的配置

看点：翻到末尾停住不回头（无 loop）· 圆点点不动（无 clickable）· 拖一下自动播放就停（无 disableOnInteraction）

第 2 轮效果 · 修正版配置

看点：末尾无缝接回第一张 · 圆点可点跳转 · 拖动后仍继续自动翻（3.2 秒/张）

答辩抽问预演

  • 第一版漏掉了哪个需求？漏了三个：loop 循环、disableOnInteraction: false（拖动后不停）、clickable: true（圆点可点）；另外 delay 没给数值，AI 自作主张填 3000——碰巧接近但这是"运气好"不是"说清楚"。
  • 第二轮怎么"说清楚"的？改成需求清单式：4 条逐条编号、每条写到参数级，再加"一条都不能少""只输出配置代码和注释"两条约束，防止 AI 自由发挥。
  • AI 第一次给的代码错在哪？语法上没错、能跑，但"理解了字面、丢了约束"：缺 loop 翻到末尾不循环；缺 disableOnInteraction 用户一动就永久停；缺 clickable 圆点成摆设；delay 3000 与需求的 3200 不符。提示词的精度决定 AI 输出的精度。

2任务二 · creative 仿写「电影墙」（AI 自学第 7 种效果）

任务要求：课堂只讲了 6 种 effect，用 AI 自学第 7 种 creative（自定义变换），参考官方示例 swiper/demo/257，为演示四新增第 7 个按钮「creative 电影墙」：上一张缩小左移带角度、下一张放大右移进场。

第 1 步 · 请 AI 讲懂官方示例的 transform 写法

我的提示词：示例里 creativeEffect.prev/next 有 translate: ["-20%", 0, -100]、rotate: [0, 0, 90]。请解释：① 数组每个位置对应什么变换？② 字符串 "-20%" 和数字 -100 的区别？③ prev 和 next 分别作用于哪张 slide？

AI 回答（要点）

  • 三个位置对应 [x, y, z]：x 水平、y 垂直、z 推向屏幕深处（负数离观众远、视觉变小）；
  • 带 % 的字符串相对 slide 自身宽/高；纯数字按像素（z 只能用 px）；
  • prev 描述上一张退场姿态，next 描述下一张待进场姿态；Swiper 按拖动进度在"姿态 ↔ 原位"间插值，所以动画连续。

第 2 步 · 让 AI 生成「电影墙」配置

我的提示词：用 effect:"creative" 实现"电影选片墙"：上一张海报缩小、左移出画面、带倾斜、渐隐；下一张停在右侧稍远处微微侧身，轮到时放大滑入居中。基础配置必须保留 loop、autoplay 3200 且 disableOnInteraction:false、pagination #wyPag4 clickable、speed 800。prev 加 shadow。

AI 回答（已并入页面 yn_buildSw4）

creativeEffect: {
  prev: {
    translate: ["-102%", 0, -160], // 左移出画面 + 推远缩小
    rotate: [0, 8, -12],           // 绕 Y/Z 轴翻转出海报倾斜角
    opacity: 0.4,                  // 渐隐，聚焦当前张
    shadow: true,                  // 投影增强"贴墙"立体感
  },
  next: {
    translate: ["55%", 0, -110],   // 在右侧偏远处待命
    rotate: [0, -6, 6],            // 微微侧身
    opacity: 0.85,
  },
}

页面接入方式：yn_buildSw4(yn_fx) 为 creative 单独准备 yn_extra.creativeEffect，与基础配置 Object.assign 合并后重建实例——其它六种效果互不影响。

第 3 步 · 追问（用自己的话作答）

prev / next 的 transform 各控制什么？prev 控制上一张"退场时变成什么样"（离开的样子：缩小、左移、斜贴、变淡）；next 控制下一张"进场前长什么样"（登场的起点：从右侧远处放大滑入）。两者只是姿态描述，真正动起来靠拖动/翻页的进度插值：进度 0 = 原位，进度 1 = 描述的姿态。

效果实验台（AI 回答的电影墙配置实况）

creative 电影墙 · 实际效果

看点：当前张左移出画、推远缩小、斜贴渐隐；下一张从右侧远处放大滑入居中（进度插值连续、跟手可拖）

答辩抽问预演

  • transform 里的百分号相对谁？相对 slide 自身宽/高：x 用宽度、y 用高度，所以 "-102%" 对任何尺寸轮播都是"恰好完整移出画面"；不带 % 的是像素，z 轴只能用像素。
  • 改一个数值让卡片转 20 度？rotate 数组第三位 z 是屏幕平面内旋转，把 prev 的 rotate: [0, 8, -12] 改成 [0, 8, -20]：退场海报多斜 8 度，像快掉下墙的海报；写正数 20 则顺时针。
  • 为什么切 creative 要 destroy + new？creative 的变换在初始化时按参数给每张 slide 绑定 transform 计算，运行中只改 effect 字符串不会重算绑定，必须销毁旧实例带新参数重建。

3任务三 · 综合创作「爱达·魔都号 + keyboard」（超纲加分项）

第 1 步 · 生成第六件展品的 slide 与图片提示词

我的提示词：光影展已有 5 张 slide（天宫/复兴号/C919/奋斗者号/天眼），结构 .swiper-slide > img + .wy-cap(h3+p)。请为第六件展品"爱达·魔都号"写：① 结构完全一致的 slide HTML；② 一条 AI 图像生成英文提示词（横版 16:9、写实海上航行、金晚霞、无文字水印）。

第 2 步 · keyboard 键盘控制（AI 第 1 轮有坑 → 修正）

我的提示词：给轮播加键盘控制按 ←/→ 翻页。注意这一页有 4 个轮播实例（#wySw1~#wySw4），如何避免互相抢方向键？

AI 第 1 轮回答（有坑）：四个实例都加 keyboard: true 即可。

实测发现"四联动"：页面较长、好几个轮播同时处于视口内，按一次 ←/→，视口内的轮播一起翻页。

第 2 轮修正提示词：只保留最后一个实验台 #wySw4 响应键盘，显式写 onlyInViewport，其它三个不加。

最终配置（写入 yn_buildSw4 基础配置，全效果通用）

keyboard: {
  enabled: true,        // 启用键盘方向键控制
  onlyInViewport: true, // 仅当轮播在视口内才响应，避免滚动页面时误触
},

第 3 步 · 追问新参数（用自己的话）

enabled 是总开关——开着才监听 document 的按键事件；onlyInViewport 是范围开关——滚进可视区域才认方向键，滚出就"让出"按键。总开关决定"谁在听"，范围开关决定"此刻谁接电话"。

答辩四连问预演

  • 这段代码什么意思？keyboard 配置让 #wySw4 监听 ←/→：enabled 打开监听，onlyInViewport 保证滚进视口才响应；魔都号 slide 与前五张逐层相同，圆点自动 5 变 6，loop 照常无缝循环。
  • AI 第一次哪里不对、改了什么？AI 让 4 个轮播都加 keyboard:true，实测"四联动"；改为只给演示四启用并显式写 onlyInViewport，按键归属清晰。
  • 新参数的作用？enabled = 总开关（监听不监听），onlyInViewport = 范围开关（此刻响不响应）。
  • 现场把 delay 改成指定值？autoplay.delay 从 3200 改 5000：每张停留 3.2 秒 → 5 秒，翻页节奏变慢、圆点高亮间隔拉长；speed:800 是动画时长不变，keyboard 与 effect 切换不受影响。

每轮效果实验台（键盘控制对照）

第 1 轮效果 · 两个轮播都 keyboard:true

按 ←/→：两个轮播一起翻页——"四联动"问题复现（课程页面是 4 个，此处以两个同屏复现同样的问题）

第 2 轮效果 · 只给一个启用 + onlyInViewport

按 ←/→：在课程页面 swiper-task.html 中只有实验台一个翻页（其余三个轮播未启用键盘，无联动）

说明：本答卷页为便于对照把实验体集中放置，若第 1 轮的两个轮播与第 2 轮的轮播同屏可见，它们都会响应方向键（各自都启用了键盘）；请滚动页面让两者不同屏，即可看到第 2 轮"独享按键"的修正效果。

补充效果 · keyboard 与 grabCursor 共存

看点：鼠标悬停在轮播上光标变"抓手"、按住拖动变"抓取中"，提示可拖拽；按 ←/→ 键盘翻页同样生效——视觉反馈与键盘输入一动一静、互不抢占

说明：grabCursor（形式参考官方示例 swiper/demo/190-grab-cursor.html）与 keyboard 均写在 yn_buildSw4 基础配置，任务四切换效果销毁重建后两者依然并存。
